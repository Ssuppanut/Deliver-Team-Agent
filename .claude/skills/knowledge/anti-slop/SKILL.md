# anti-slop

The design-quality knowledge base behind `slop-guard`, the same way
`universal-design` sits behind `a11y-guard`. "Slop" is the tell of unconsidered,
machine-generated UI. Every item below is a decision the spec author makes so the
output looks authored, not autogenerated.

## The checklist

1. **A chosen palette, not the default.** Ship a real brand/semantic ramp, never
   framework defaults (`indigo-500`, `blue-600` as the accent by accident). In
   this system that means components consume **semantic tokens** only —
   `token-guard` already rejects raw values, which forecloses the most common
   slop.
2. **State by icon + text, not color alone.** Severity/status must survive
   grayscale and CVD. A color-only variant is a `slop-guard` `status-color-only`
   finding — pair it with a per-state icon or explicit text.
3. **No emoji in the UI.** Real icons come from the unified icon token system
   (lucide / SF Symbols / Material). Emoji in output is a blocking `no-emoji`
   finding.
4. **Flat surfaces over decoration.** No gratuitous accent rails, gradients, or
   drop shadows standing in for hierarchy. Use spacing and type weight (see
   `design-principles`).
5. **Real scales.** Radius and spacing come from the token scale, not ad-hoc
   values — one `radius.*` / `space.*` step per level, not a new number each time.
6. **Both themes designed.** Light and dark are each considered, not a naive
   invert. (Token-level concern; keep semantic pairs that hold contrast in both.)
7. **One icon library per platform.** Never mix icon sets — the icon token map
   enforces this per adapter.

## How it connects

- Enforced by `slop-guard` (`no-emoji`, `status-color-only`).
- Reinforced by `token-guard` (no raw values) and `universal-design` (the
  color-alone rule is also an a11y rule).
- Applied during `04-design`: choose semantic tokens, give status an icon or
  text, never reach for an emoji.
